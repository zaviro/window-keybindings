Draft v0.3 · 语义寻址优先

创建后可以忘记，想要时按语义回来

核心仍然只有三种主要寻址：知道角色就直达，知道名字就搜索，只想回到刚才就用历史。Alias 与方向组合只进入未来实验层，不占当前核心键位。

知道角色Mod+B / Mod+T

focus-or-create

知道名字Mod+D

Noctalia 搜 window / app / workspace

回到刚才Mod+Tab

保留 niri recent windows

1

Role：只保留真正高频对象

B / T 进入核心；E / A 只保留语义槽位
Mod+B暂定
当前 workspace browser：已有则 focus，没有则创建。
Mod+T暂定
当前 workspace terminal：沿用 niri 的 T=Terminal，但升级成 focus-or-create。
Mod+Alt+B暂定
global-main browser：存在于别处就拉到当前 workspace。
Mod+Alt+T待验证
global-main terminal：逻辑相同，但长期价值待实测。
Mod+E保留不绑定
Editor role 名称保留，暂不建立肌肉记忆。
Mod+A保留不绑定
AI / Assistant role 名称保留，等出现稳定高频对象再启用。
2

搜索：只保留 Mod+D

优先复用 Noctalia

Mod+D 打开统一 Destination Search；窗口结果跳转，应用结果启动，workspace 结果按名进入。

Chrome — GitHub [window] → 跳转 Google Chrome [application] → 启动 window-keybindings [workspace] → 进入

不再保留 Mod+Space 第二入口。

3

Workspace：名字是身份

数字只是快速槽位

长期 workspace 使用名字；Mod+1..9 只是稳定别名。忘记数字后仍可 Mod+D 输入名称找回。

1 → main 2 → window-keybindings 3 → learning
4

niri 原生能力全部保留

语义层是加法，不替代窗口管理器

Mod+O/Q/F/R/V/Shift+F/Tab、方向 focus、窗口/列移动、workspace 重排、consume/expel、resize、center、expand 等都保留，作为完整空间操作与 fallback。

5

Future：Semantic Alias

把少量真实高频对象升级成自定义 O(1) 地址
Future / Experimental

Alias 与 role 使用同一种行为：已有则跳转/召回，没有则创建；但 alias 由用户定义，适合无法抽象成 browser/terminal 的稳定高频对象。

Mod+M → music Mod+C → ChatGPT Mod+G → 某个固定 GitHub / browser profile
约束：Alias 不能重新退化成 mark 系统。只有少量真正高频目标才升级；长尾对象继续走 Mod+D 搜索。
6

Future：Directional Activation

一次完成保留当前窗口 + 激活目标 + 排列
Future / Experimental

当前首选规则：箭头表示目标窗口的最终位置。

Mod + ← + B → [ Browser ][ Current ] Mod + → + B → [ Current ][ Browser ] Mod + ↑ + T → Terminal 在 Current 上方 Mod + ↓ + T → Terminal 在 Current 下方

这比“← 表示原窗口放左边”少一层反向推理：← Browser 可以直接读成“Browser 放左边”。

理想组合语法

Alt → 目标作用域 方向 → 目标最终位置 B/T/Alias → 目标对象

因此未来理论上可以有 Mod+Alt+←+B：把 global-main Browser 拉来并放左侧。

尚未决定

  • 目标已经可见时是否重排；
  • 已有两窗/三窗时是新增、替换还是重构；
  • 默认比例 50/50 还是 60/40；
  • 执行后 focus target 还是保留 Current；
  • niri / Hyprland 中真实物理输入采用 chord、leader、submap 还是 helper。
7

实现边界：niri 默认不是 focus-or-create

需要很薄的语义 helper
key → helper → query windows → match ? focus-window : spawn

global-main 再增加 move-window-to-workspace。Alias 将来复用同一 helper，而不是再造一套机制。
