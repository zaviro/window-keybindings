# Window Keybindings

一套面向键盘流桌面的**窗口、工作区与布局交互规范草案**。

本仓库当前只讨论行为、语义、快捷键与设计理由，**不包含任何 niri、Hyprland 或其他 compositor 的实现**。先把用户模型确定下来，再决定实现方式。

## 核心目标

传统窗口管理器常把窗口的物理位置、创建顺序或最近使用顺序当作主要寻址方式：

- “向左两次找到浏览器”；
- “Alt+Tab 三次找到终端”；
- “记住项目在 workspace 4”；
- “记住某个 scratchpad/mark 的名字”。

本规范反过来把**语义身份**作为第一入口：

> 用户只需要知道自己想去哪里，不需要记住那个窗口现在在哪里。

因此：

- 浏览器是 `browser`，不是“左边第三个窗口”；
- 终端是 `terminal`，不是“刚才 Alt+Tab 的第二项”；
- 工作区有名字，数字只是稳定的快速入口；
- 普通窗口可通过名称搜索，创建后允许遗忘；
- 物理布局只在窗口同时可见、需要组合屏幕时才有意义；
- 后台窗口之间的左右、先后顺序原则上没有用户语义。

## 设计原则摘要

1. **创建自由，创建后可遗忘。**
2. **切换无代价。** 已知目标应 O(1) 直达；未知目标应以 2–3 个字符搜索直达。
3. **位置不是身份。** 后台窗口无需稳定空间顺序。
4. **名称优于匿名编号。** workspace 必须拥有可理解的语义名称；`1..9` 只是可选快捷别名。
5. **明确区分“切换/复用”和“新建”。** 避免因为导航而不断制造实例。
6. **Local 与 Global Main 是两个作用域。** 当前任务实例和全局主实例使用不同快捷键。
7. **Global Main 是可漫游对象。** 召回时把实例拉到当前 workspace，而不是把用户送去实例原来的位置。
8. **历史只负责“回到刚才”。** `Mod+Tab` 不承担寻找任意窗口的职责。
9. **方向只负责可见空间关系。** `Mod+方向` 不应成为寻找后台窗口的主要方式。
10. **布局变化必须显式。** 普通“去某窗口”与“保留当前窗口并分屏加入目标”应是两个不同意图。
11. **快捷键形成语法，而不是散乱记忆。** `Alt`、`Shift`、`Ctrl` 应尽量具有稳定的作用域/结构语义。
12. **规范独立于 compositor。** niri、Hyprland、COSMIC 等只能是不同后端。

## 当前状态

**Draft v0.1 — 仅用于讨论。**

尤其尚未最终确定：

- 搜索入口与“强制新建”入口的最终按键；
- 分屏的物理快捷键语法；
- 普通语义切换是否总是进入单窗口视图，还是保留已有 composition；
- 多显示器上的 workspace / global-main 规则；
- 一个 workspace 内存在多个同应用窗口时，哪个实例拥有 local role；
- 浏览器多 profile、终端多用途等更细角色如何表达。

在这些问题达成共识前，不应把任何 compositor 的当前限制写成规范本身。
